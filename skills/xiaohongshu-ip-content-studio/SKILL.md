# 小红书热点×IP内容工作流

目标：把热点与账号视角结合，形成有传播潜力的故事、观点、知识或视觉内容，同时积累 IP 记忆。形式按选题和用户需要选择，区分判断与事实，不承诺爆款。

## 识别请求与账号

- 只要求生成/编辑已确定内容的一幅插画、封面或其他视觉素材，且不要求热点研究或平台事实时，作为纯视觉子任务直接使用 imagegen；只检查该阶段依赖，不启动社交调研；仅交付请求的图片和生成记录，不额外写整套标题/正文/话题。完整笔记/热点创作仍遵循研究与选题流程。

- “检查/安装依赖”“初始化”：先执行下方依赖引导；用户只要求设置时不提交研究、不生图、不索要角色设定。
- 只给领域、情绪或“今天热点”：调研后提供最多三个有依据的候选题，保存进度，等待用户选择。合适题目不足时不凑数。
- 用户选中候选题，或已明确具体笔记题目并要求制作：复用匹配研究，完成文案、页面方案、图片和归档，不再逐环节确认。明确题目不代表研究已完成，仍须取得匹配证据。
- “选第二个”“继续”：当前对话明确绑定批次时继续该批；新聊天无绑定时读取该账号待选批次，只有一个则继续，多个批次均含该编号则列日期和题名询问一次。不单凭最新时间替用户选择，不重造或重排候选。
- 只改标题、正文、某张图、话题、头像、背景、简介：只处理请求部分，复用当前研究和 IP，不全流程重跑。
- 提供发布数据并要求复盘：直接复盘，不重新检索或生图。

分享版默认使用安装者自己的账号。先读取已有活动档案；首次没有账号信息时，只问角色/定位与可用参考这一个必要问题。用户已提供足够信息就直接建档，不重复询问。使用[账号模板](references/accounts/template.md)建立独立设定、资产和空历史。

[黄小歇档案](references/accounts/huangxiaoxie.md)仅为只读示例，其形象、设定与图片不适用工作流的 MIT 许可，见[示例素材范围](assets/huangxiaoxie/NOTICE.md)。不要自动用该角色替安装者制作公开内容；用户明确表示本人为作者或已有使用授权时，才可启用这个账号。无需用户提交身份凭据。

默认归档根目录为首次运行时实际工作目录下的 outputs/xiaohongshu-ip-content-studio，首次解析后登记账号位置。同一工作目录的新聊天先读其中的 accounts.json；更换工作目录时使用用户提供的已有归档位置。未知时问一次，不承诺跨目录自动发现，也不自动扫描用户主目录。

首次归档和跨聊天续跑前读取[归档约定](references/archive-and-review.md)。当前用户指令优先于活动账号档案，活动档案优先于打包初始档案。不因一次修改或图片失败改变长期人设。

## 首次自检与依赖补装

首次使用或缺少阶段依赖时读取[安装与连接引导](references/setup.md)，并使用[来源清单](references/dependencies.json)。scripts/setup_dependencies.py 默认只读；已有用户明确安装授权时可 --install 调用客户端现有 skill-installer helper，跳过已存在项且不覆盖，补装清单内两个技能。

分开报告技能文件、工具可见性和服务认证。插件缺失时用客户端真实插件发现/安装入口或 SignalDig 官方连接向导；建议 pending 不是已安装。受保护授权由用户在客户端完成，不自动改配置或权限。生图内置能力不能靠下载同名技能获得，不自动接付费 API。

仅“检查”不安装；普通创作请求尚无安装授权时一次列明缺项与来源申请补装。默认调用提示已明确“检查并安装既定缺项”时直接沿用该授权，不重复确认。只改稿、只复盘不触发无关依赖安装。

## 依赖按阶段加载

这是技能编排，不存在调用另一个 Skill 的虚构函数。按客户端技能目录找到并读取相应 SKILL.md，由本代理执行其工具。不复制过时接口或修改依赖。

| 阶段 | 技能 | 交接内容 |
| --- | --- | --- |
| 热点、笔记、话题证据 | research-growth-signals | 账号边界、用户题目、平台、时效与预算 |
| 选题后写作 | xiaohongshu-post-creator | 终态研究、已读样本与限制、已选题目、账号口吻 |
| 最终图片 | imagegen | 定稿页面方案、角色或品牌参考、精确文字、生成顺序 |

从当前技能清单解析路径；通常前两者位于用户技能目录，imagegen 由系统/客户端提供。路径变化先搜索，不直接宣称缺失。缺少项按上方引导补装既定技能或连接；不擅自安装替代品或升级现有技能。

研究协议与 imagegen 的内置工具/回退边界继续适用。xiaohongshu-post-creator 负责文案和画面说明；本编排按选定形式把页面方案交给 imagegen 生成图片。

## 内容形式

选题时读取[形式选择](references/content-formats.md)。支持漫画、插画、知识/观点卡片、教程/清单和生活方式图文；用户指定形式优先，否则依选题、读者任务和账号偏好推荐一种。IP 可为角色、真人作者、品牌或编辑视角，不强加虚构主角。仅支持静态图文，依赖与实际工具能力不变。

## 1. 研究与候选题

读取[运营方法](references/content-operations.md)的“研究与候选题”。发现实际可见的 research_social_signals 标识，不拼接 MCP 别名。

- 默认只用小红书。宽泛热点请求可先取一次当前推荐词响应，再做一次与 IP 有关的笔记研究；指定题目直接用已有线索，不额外跑推荐词。两项分别保存完整 analysis_id。
- 默认笔记预算最多 20 条、standard、refresh=false。当下热点默认近七天意图；不支持时间约束时按实际返回日期判断，不虚构过滤成功。
- 每项任务只提交一次，按返回时间轮询至终态，再用正确 Dataset 读结果。默认只读一个结果页，按实际读取数报告，不无限追页。
- 匹配终态证据可复用。新日期问“今天热点”时旧材料只作历史参考，做必要本轮研究；不因此擅设 refresh=true。用户明确强制刷新才使用它。
- 匹配须结合原始用户请求、实际提交范围与已读样本判断；历史导入缺失查询范围时记未知，不把 completed 当成适用于新题的证明。创作延展与被证实的平台事实分开。
- 研究进行中失联、认证拒绝、失败或空结果按研究技能处理；首次缺依赖先执行安装与连接引导。不能反复安装来处理普通查询错误，不以常识模拟实时结果。部分成功证据保留，近期依据不足标为“常青备选”。
- 不主动扩展平台、关键词、时间或预算；候选阶段说明具体补查需求，由用户选择。

候选题包含：稳定编号、链接与日期/实际互动、时效判断和局限、点开/看完/分享动机、账号连接、推荐形式及理由、暂定标题与封面、内容价值或适用的故事冲突、账号记忆点。传播判断标为判断，不给虚假热度分数。

保存 research.json、topics.md、run.json，更新历史为“候选”，然后等待用户选择，不提前写完三篇或批量生封面。

## 2. 选定后连续制作

读取运营方法的“成稿与话题”，加载 xiaohongshu-post-creator，直接复用已有终态证据，不重复提交相同研究。

正式新制作仍执行依赖技能的可用性门槛：工具缺失或认证拒绝时停下，不以缓存绕过。工具可用且证据范围匹配时，“复用”不要求重新 submit；历史证据可支持明确标注的常青创作，不能支持本轮实时热点断言。离线演练仅验证决策，不算完成实时研究或生图。

交付一个主标题、两个文字备选、一篇正文、一套匹配话题和一版实际封面。备选标题不各生一套图；来源与限制单列，不塞进可发布正文。

读取[视觉连续性](references/visual-continuity.md)，先定有限完整的页面方案，再生图。页数由内容决定。通用字段为用途、核心信息、布局、精确文字、参考与验收点；漫画加分镜/对白，卡片加信息层级，教程加步骤，不强填不适用字段。

检查标题承诺、封面、正文与页面内容一致。故事型内容通过动作对白表达；知识与教程强调论据和步骤；插画强调场景与文字关系。避免套话、假经历和复制他人文案/版式。

## 3. 生图与修复

加载 imagegen 并发现内置工具。先看本地参考，生成并检查首图；合格后继续。每张独立调用工具，持续提供固定角色/品牌参考和本篇首图，不用 n 代替不同页面。

默认 3:4 竖图，风格跟随账号。需要角色而身份不清且无参考时只问关键设定；不含角色的内容直接遵循品牌/栏目视觉。角色设定明确时可用首张合格画面建立自己的参考，不偷用黄小歇。不自动额外做头像和背景。

实际逐图核对身份、风格、文字、动作/肢体、裁切与连续性；不把提示词已要求视为已达标。每页最多一次连接重试及一轮定向质量修复；仍失败记待补，不静默丢参考或改 CLI。

成功图片立即复制到本批 images/，保留原件和修订版本，记录完整提示词、生成方式、参考图与质检结果。

## 4. 交付、历史与复盘

按归档约定保存来源、成稿、页面方案、提示词、编号图片和真实状态；更新账号历史。提供发布顺序、实际原图链接和 ZIP，不把图片只留在默认生成目录。

对用户简洁交代：

- 做完了：选题理由或成稿、图片、话题；来源和限制单列。
- 需要你：只列真正需要的选择或素材，没有就不加多余问题。
- 知会：待补页、证据时效、已读页数/数量和剩余结果。未发布不称已发布。

用户提供数据并要求时按归档约定复盘：保留缺失项，只算口径明确的比例，提出一个优先调整变量。未经请求不登录后台、发布、评论或定时监测。

## 账号与真实性边界

- 默认不把“AI漫画”等制作方式词加进公开标题、话题或简介；用户可按账号目标调整。内部制作记录如实保留，不虚称手绘、实拍、实测或用户亲历。
- 已验证话题必须在返回的明确标签中出现，标题或普通用语不自动算话题；自建标签单列。点赞不等于话题浏览量或流量归因。
- 历史只记录实际选过/做过/用户确认发布过什么。生成不等于发布，角色故事不等于用户真实经历。
- 制作授权不包括发布、切付费工具或改客户端配置。无需新建项目，不索取已有 MCP 密钥。
