# 归档、选题等待与续跑

## 位置与隔离

打包账号档案是初始设定；活动档案与历史写账号归档，不在每次创作时改已安装 Skill。

不在分享文件中写原作者的绝对目录。首次默认把当时实际工作目录下的 outputs/xiaohongshu-ip-content-studio 解析为归档根目录；用户明确指定的目录优先。解析结果写入运行时 accounts.json，不写回随 Skill 发布的模板。

accounts.json 保存格式版本和账号清单，每项记录 account_id、display_name、archive_root 与 profile_path；profile_path 相对其所属 archive_root 解析。运行时可以保存本机绝对归档位置，但这些记录不进入发布仓库。新账号按 account_id 分开，索引存在时先查，避免重建历史；同名多项问一次。

同一工作目录的新聊天读取本地默认入口，或当前用户明确提供的归档根目录。换工作目录时不能假定索引仍可见：用户给出了旧目录就从那里读，未给且当前目录找不到时，只问已有归档位置。不要因换目录偷偷创建另一个同名账号。用户明确表示首次使用时才初始化空索引/空历史。

不用创建新项目，也不要求修改客户端配置、环境变量或 MCP 密钥。不在安装目录写索引或缓存。归档位置无权限时按客户端机制处理，不静默换位置。

长期账号设定明确更改时递增 profile_version 并保留旧设定；只对本篇生效的用户指令写入 run.json 的请求/覆盖项，不自动改长期档案。

archive_root 下按 account_id 隔离：

    account.md
    history.json
    assets/                      用户新增/修订参考
    runs/<本地日期时间-题目短名>/
        run.json
        research.json
        topics.md
        post.md
        storyboard.md
        prompts.txt
        images/
        review.md                仅复盘时

只在相关阶段创建文件，不堆空占位。新聊天先从 accounts.json 读取活动 account.md、history.json 和匹配 run.json，检查真实文件。归档移动、丢失或权限受限时说明具体缺口，利用客户端授权或询问新位置，不假装有历史、不静默换位置。

## 旧名称与已有归档

新名称为 xiaohongshu-ip-content-studio，旧名为 xiaohongshu-ip-studio。优先用户明确给出的归档位置及账号档案；不重写既有绝对路径、run_id、历史或制作文件。

没有显式位置时检查当前工作目录新默认入口；若没有记录而旧 outputs/xiaohongshu-ip-studio/accounts.json 存在，则沿用旧根目录。有两份不同有效索引且用户未绑定时询问一次，不合并、不迁移覆盖、不新建空历史。

若旧目录没有 accounts.json，但在用户明确给出的根目录或同工作目录旧默认根目录中存在 account.md/history.json，则只在该根目录下一层定位账号，不扫描主目录。已知账号直接读取；单个候选可恢复，多账号且未明确时问一次。验证现有文件后可补建指向旧资料的索引，不覆盖档案或初始化空历史。

## 最小记录

run.json 至少保留：

| 字段 | 真实内容 |
| --- | --- |
| version / run_id / account_id | 格式版本、唯一批次、账号 |
| account_profile_version / created_at / timezone | 档案版本与用户本地时间 |
| stage | researching / awaiting_topic / producing / partial / ready / failed |
| user_request | 真实请求与范围 |
| research | 完整 analysis_id、实际状态、research.json 路径 |
| candidates / selected_topic_id | 稳定编号，未选择时为 null |
| content_format | 本篇选定的静态图文形式；旧批次缺少时依据现有文件理解，不强行回填 |
| planned_pages / images | 有限页清单；每页路径、质检、实际重试及修复次数 |
| artifacts / missing | 真正存在的产物与待补项 |
| publication | 未知或用户确认的发布状态/链接/时间 |

research.json 仅存公开证据和可追溯状态：完整 analysis_id、范围/终态、收集数/已读数/页数、链接/ID、原样摘要/明确标签、日期与分列指标、coverage/limitations/has_more 和真实返回的续读值。不存内部跟踪、凭证或伪造结果。

实际提交的 request、scope 和 search 原样保留，以便判断是否匹配后续题目；旧导入没有的字段标为未知，不能补造。服务的采集页数与代理读取结果的页数分别记录，不能用 coverage.pages_fetched 冒充已读页数。

topics.md 保留原候选稳定编号，不重排后改变“第二个”的含义。post.md 区分可发布正文与创作说明。storyboard.md 继续作为兼容文件名，保存页面方案；按形式包含镜头/台词、卡片信息层级或教程步骤；prompts.txt 如实保存实际最终提示词、模式和参考。

## 状态与中断

- researching：有 ID 就续查，不能因慢或中断重新提交。
- awaiting_topic：保存候选并停下；没回复不是确认，不提前生图。
- 续跑绑定：优先当前对话已明确绑定的 run_id；新聊天未绑定时，单个待选批次可直接匹配，多批次均有该编号则列实际日期、标题确认一次，不自动挑最新。确认后保持候选稳定编号。
- producing：选题已确定，连续完成；重开聊天只补缺项，保留合格页。
- partial：保存成功产物与待补原因；重试预算不因换聊天清零。
- ready：请求所需的所有产物真实存在且一致。仅文案请求可按范围完成，但不能称整套图文完成。
- failed：必要阶段不可进行，保留旧成果，不能变成虚构研究。

用户换题保留选择和修订记录；新题在旧研究范围内才复用。范围变更或研究时效不再支持当前请求时才做必要新研究，局部改稿/修图不自动重查。

## 历史与制作包

history.json 每批记录题目、证据类别、主题、内容形式、核心问题/信息价值、结构、适用的情绪矛盾或梗、收尾、档案版本、批次位置和最近状态。展示区分“候选”“已制作”“用户确认已发布”，部分/失败也真实记录。

用户确认发布后才补链接、发布时间和标记。更新当前批次，不丢旧批次，不覆盖其他账号。新安装者的 history.json 初始为空；打包的示例故事不代表安装者已制作或已发布，不能导入为真实历史。历史研究不作为以后实时证据。

交付发布顺序、实际原图和 ZIP。ZIP 含发布稿、页面方案、最终提示词、合格图及简洁来源说明；执行重试记录留批次目录，不进正文。partial 包文件名/说明标出未完成。

## 按需复盘

只在用户提供数据并要求复盘时做。明确对应账号、笔记、版本、发布时间、观测时间/时长、指标口径；能从资料发现的不重复问。原数值保留，缺失为 null。

- 曝光、阅读/播放、赞、收藏、评论、分享、主页访问、新增关注分开，不拼接不同来源或时点。
- 分子、分母、窗口、定义一致且明确时才算比例，写出公式。分母为零则不可计算。
- 赞/阅读、收藏/阅读等动作数比例不是去重读者比例，不能混称用户转化率。不能只凭阅读总数判低、只凭缺少数据的漏斗诊断封面问题。
- 无曝光不算点击率，无明确关注归因不说本篇涨粉；缺同口径历史不伪造基准。
- 优先本账号、相近题材、相同观察时长；指标不足做内容诊断并标假设。
- 每次一个优先变量和待验证假设，存 review.md 与历史，不冒充受控 A/B。

复盘不自动改长期角色或画风。需要长期改变时由用户明确要求。不自动登录后台、发帖、留言、监控或安排定时任务。
