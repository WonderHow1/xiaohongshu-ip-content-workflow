# 依赖自检、补装与连接

首次使用、用户说“安装/检查依赖”，或阶段缺少技能/工具时读取。本引导只处理本工作流的既定依赖，不创建新项目、不索取聊天明文密钥、不改用户全局权限。

## 区分四件事

1. 技能文件存在且名称匹配。
2. 插件已安装或 MCP 已配置。
3. 当前会话看得见正确工具。
4. 服务实际调用成功且授权有效。

前一项不证明后一项。自检脚本只检查文件及代理提供的可见工具名称，不能登录、确认认证、安装内置生图能力或代替用户授权。首次真实研究请求同时验证服务，不额外提交付费“测试研究”。

## 何时可以安装

用户明确要求“检查并安装依赖”，或已批准本会话列明的缺失技能与来源时，直接执行已有授权，不重复询问。只有普通创作请求、尚无安装授权时，先检查并一次性列出缺少项、可信来源和写入位置，请用户授权补装；不要由技能文本自行授予写权限。

源码安装遵守客户端网络/文件权限。需申请时仅申请实际技能目标目录及必要网络；被拒绝就保留检查结果，不改临时目录冒充已安装。用户只说“检查”时绝不安装。

## A. 自检

1. 从当前技能清单和可见工具发现依赖，不只检查一个默认目录。已知插件/自定义位置可用脚本的 --skill-path 传入；不递归扫描整个主目录。
2. 脚本位于本 Skill 的 scripts/setup_dependencies.py，默认只读。默认搜索 CODEX_HOME/skills、用户 .agents/skills、当前目录 .agents/skills 及对应 .system 子目录；--dest/--skill-root 可适配客户端实际目录。
3. 代理已检查工具清单时传 --tools-checked，并用 --available-tool 传实际可见的 social research 与内置 imagegen 标识；否则工具状态为 unknown，不能当作不存在或已连接。
4. 为用户简洁报告技能 present/missing/invalid、工具 visible/unknown/missing 与仍需的授权。不要粘贴路径清单或内部 JSON 当完成回执。

只读检查命令（从本 Skill 目录运行）：

    python3 scripts/setup_dependencies.py --check

可以只跑此检查，不要求装插件或联网。

## B. 自动补装两个技能

可信来源定义在[依赖清单](dependencies.json)。研究技能来自 seo-signal-skills 的 v2.2.0；写作技能来自 social-marketing-skills 的 main。两者不是同一个仓库。不将上游技能源码复制到本发布包。

优先加载客户端现有 skill-installer，用其安装 helper。该客户端不提供安装 helper 时，脚本只输出 needs_client_installer，交给客户端实际支持的安装入口，不能虚构安装成功。

本 Skill 的脚本可自动跳过已存在的技能，调用该现有 helper 补齐缺项：

    python3 scripts/setup_dependencies.py --install

必要参数：

- --installer-script：从当前 skill-installer 找到的真实 helper 路径。
- --dest：客户端实际用户技能目录；不能想当然写系统目录。
- --skill-root 或 --skill-path：已安装在其他位置的技能，避免重复安装。
- --only-specified-roots：只查显式目录，适合隔离检查或客户端限定目录。
- --only-skill：只补装当前阶段实际需要的既定 GitHub 技能，可重复指定；默认初始化补两个。只做研究时可选 research-growth-signals，不能用它安装内置 imagegen。
- --method：现有 helper 支持的 auto/download/git；默认 auto。
- --timeout：每项安装等待上限，默认 90 秒；超时不无限重试。

脚本只安装清单里的两个 GitHub 技能；使用参数数组，不执行 shell 命令字符串。每项一次安装尝试，先前成功项保留。网络失败可在代理明确说明后同源重试一次，例如改 git；不换镜像/仓库，不自动升级或覆盖现有目录。现有目录损坏或名称不符时标 invalid，先保留，不能强行删除重装。

--check 退出成功仅表示检查已完成；--install 若两个 GitHub 技能仍有缺项则非零退出。插件授权、认证和内置生图状态仍须单独检查，不能只看进程退出码。

限定 --only-skill 时，退出码和 requested_install_complete 只表示所选安装项；preflight_complete 仍检查整套能力，不能因单阶段补装成功就说全流程就绪。工具状态 unknown 时先检查清单，不直接让用户重新连接。

helper 返回成功后再次读取实际 SKILL.md 核对名称；运行时仍重新加载技能。若当前会话尚未识别，说明需按客户端指引重新加载/开启下一轮，不把文件复制视为工具已出现。

## C. 插件与 SignalDig 连接

已有可用 SignalDig 工具时复用现有连接，不重复建议安装。缺工具时：

1. 若客户端有插件管理能力，加载 plugin-management 并搜索 SignalDig，使用本轮真实返回的精确 ID。
2. 有相关未安装且可用插件时，使用客户端安装建议/安装入口；pending 不是 installed，更不是 connected。安装建议最多一次，不自动更改权限或替用户确认 OAuth/密钥。
3. 搜索无结果或未提供插件管理工具时，继续[官方接入流程](https://signaldig.com/agent-setup)。没有目录结果不代表服务不存在。
4. 优先沿用 agents/openai.yaml 的既有依赖声明及客户端原生连接向导。当前客户端没有可执行的安装/连接 API，就打开或给出该向导，只保留最少的用户动作；不假称已配置，不要求新建项目或让用户手改配置。
5. API key 只进入客户端受保护的 Secret/密码字段；不让用户发到聊天，不存仓库、运行 JSON 或脚本参数。没有保护字段就停在授权步骤。
6. 完成授权后重新检查可见工具。实际研究成功前，准确说“工具可见、认证尚未由请求验证”，不假报已连接可用。

不调用权限修改工具来关闭确认，也不新增未声明的第三方服务。单独声明 MCP 依赖不是保证所有客户端自动连接。

## D. 内置 imagegen

先查系统/插件技能清单与原生生图工具。两者都需要；CLI 型同名技能或下载教程不能让不支持生图的客户端获得内置能力。

不为原生生图搜索第三方插件，不自动安装付费绘图 API，不索取 OPENAI_API_KEY。只有用户明确选择回退时才按 imagegen 的 CLI 规则处理。缺内置能力时说明需要支持它的客户端，研究、选题或文案能独立做的部分继续，图片记为待完成。

## 完成与恢复

每次阶段缺项时只补缺少的部分；已安装项不重装，不反复开启授权流程。研究技能/工具就绪可继续调研，生图缺失无需阻止独立选题；全套图文仍须实际生图验收。

可将 setup 结果写到使用者本地批次目录，忽略发布；只记录名称、状态、时间与所需下一步，不记录密钥。没有发起真实研究、生图或授权完成时，不能在结果中伪造这些完成状态。
