# 按选题选择表达形式

本工作流支持静态图文，不把所有内容转成漫画。用户明确指定形式时遵从；否则结合选题目的、读者任务、账号长期视觉和现有素材，给出适合的一种形式及理由。形式选择放进候选题，用户选题后不再为常规排版重复确认。

| 形式 | 适合内容 | 页面方案与验收 |
| --- | --- | --- |
| 漫画/对话小剧场 | 人物关系、生活冲突、幽默或情绪共鸣 | 有限分镜、动作、对白归属与转折；角色连续，不强加固定页数 |
| 插画/氛围图文 | 情绪、生活观察、场景体验、视觉表达 | 场景、主体、色彩及图文关系；可单图，不强制对白或反转 |
| 知识/观点卡片 | 解释概念、比较观点、总结有依据的信息 | 每页一个重点、标题层级、短论据/来源；不编数据，不强加拟人主角 |
| 教程/清单图 | 可核实的步骤、方法、检查清单 | 顺序、前提与注意点，图示对应正文；需要事实或实测的部分先取得来源，不能虚构“我实测” |
| 生活方式视觉/封面海报 | 场景展示、物品主题、作品封面 | 主体、构图、留白和文字；生成的写实风格图不能称为用户实拍、实际到店或真实体验 |

同一账号可以采用不同形式，保持的是角色/品牌身份、配色、字体、语气和表达立场。换形式不等于重设永久画风。当前账号偏爱简约漫画时仍可默认漫画，用户指定卡片或插画则按本篇需求调整；不把偏好当唯一允许形式。

账号 IP 可以是虚构角色、真人作者、品牌或稳定的编辑视角。没有角色或真人参考时不强造黄猫、对白或个人经历；使用品牌/栏目视觉规范保持统一。人物、物品和图表按实际页面需要出现，不要求每页露脸。

## 共同内容骨架

先明确本篇为读者提供什么：故事/共鸣、观点、解释、步骤或视觉体验。标题承诺、正文、封面和内页必须对应。漫画用冲突与动作，知识卡用问题和论证，教程用步骤和结果，插画用场景与文字关系；不用故事三段式硬套所有模式。

社交样本只证明相关讨论与互动，不自动证明教程正确或知识结论成立。事实性观点和步骤使用可靠来源核实，缺少依据时标待核实或移除，不能用“高赞”代替正确性。

## 页面交接

storyboard.md 保留为兼容文件名，内容标题改为“页面方案”。通用字段为页码/用途、核心信息、布局/构图、精确画面文字、参考资源与验收点；只有适用时增加镜头、动作、对白、步骤或数据来源，不硬填不适用字段。

实际生图继续使用 imagegen；根据模式选择其当前对应的 illustration-story、stylized-concept、infographic-diagram 或 photorealistic-natural 等分类，遵循该技能最新规则。图中文字密集时先简化信息，不靠小字堆满页面。

仅要文字或只有一张封面时按用户范围交付，不额外补全套图。本工作流不因扩大图文形式而承诺视频、音频或动画生成功能。
